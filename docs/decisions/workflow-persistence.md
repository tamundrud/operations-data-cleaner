# Workflow persistence and portable backups

Date: 2026-10-15. Scope: master-plan U4; copy/constants/trim and delivered CSV settings only.

The version 1 workflow remains the only configuration model. Structural decoding continues to describe the finite MVP grammar; the usable-configuration codec additionally rejects incomplete, inconsistent, incompatible or undelivered capabilities. Import and stored-record reads use that boundary before activation. Editor snapshots explicitly project configuration and derive referenced source headers from recipes. Actual encoded JSON is limited to 1 MiB and nesting to 20; exact decimal strings, optional blanks, field identities/order and configured CSV choices retain their meaning. Dates/arithmetic/Excel await their own units; no migrations from a nonexistent older format are added.

Native IndexedDB database `operations-data-cleaner-workflows`, database version 1, contains one `workflows` store with key path `id`. Records contain exactly `{id, json}`. The JSON is the same versioned portable configuration downloaded by the user. Database version is independent of workflow format version. Source files, filenames, parsed data, preview values, source-row IDs, issues, correction overlays and formula-handling permissions are excluded. Deliberately configured field names, workflow names and constants are configuration and may reveal business information.

Only explicit Save writes an entry. Local Save requires a nonblank name; JSON import opens an unsaved working draft. An unnamed valid workflow can still be downloaded. A new durable draft receives a UUID, ordinary saves/downloads retain identity, and an explicit copy receives a new identity and a distinct name. Names compare with deterministic whitespace/case normalization. Every inserted output field gets a fresh UUID, avoiding imported field-ID collisions.

An explicit update uses the saved target's previous serialized snapshot. In one readwrite transaction, the adapter reads the current records, rechecks identity/name conflicts and the expected target, and writes. Completion is acknowledged on transaction completion, never request success. A concurrent modification rejects the stale update; it is not silently retried. Corrupt/future records are left untouched and reported separately. Denied, blocked, quota and aborted operations remain local workflow errors; the active conversion and portable download remain usable. Connections close after each operation and on version change; cancelled/blocked opens close a late connection rather than activating it.

Opening a configuration validates first, asks before discarding an active conversion or unsaved draft, then ends the old session and installs the configuration before source upload. It clears old file/worker/page/choice/editor state and invalidates asynchronous selections. Retry cannot recover the previous file after activation. The stored source delimiter is the policy from a successfully committed source import, including `auto`; detected delimiters, a pending next-upload picker and destination-template parsing cannot rewrite that policy.

Preview freshness and unsaved configuration are distinct. Saving captures an immutable validated configuration even while preview work is pending; successful completion advances only the submitted saved baseline. Newer edits stay unsaved. Export still requires the current evaluated dataset and a fresh formula choice when applicable. Saved/imported workflows start with upload/review/export; Edit workflow reveals the unchanged paired-card editor and contextual settings.

Browser storage is origin/browser-specific and can be cleared. The first successful new-entry save offers a nonblocking portable-backup reminder; Download workflow remains available independently of storage. JSON uses a local Blob with `application/json` and fixed `workflow.json`, with URL cleanup. A download initiation cannot prove durable disk backup. There is no cloud synchronization, automatic database reset, source history, storage permission prompt or localStorage fallback.

Tests cover real native browser transactions and downloads, plus controlled request seams for reproducible abort/denial/cancellation cases. Privacy interception allows only fixed same-origin static assets, including during saved reuse and portable transfer to a second local origin. Storage assertions whitelist configuration structure and inspect every record; they do not broadly permit source content because IndexedDB now exists.
